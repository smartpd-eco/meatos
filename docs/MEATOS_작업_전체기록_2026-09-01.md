## 2. POS 규격외 수집 — 문제 진단

데이터가 누락되는 지점 2곳:

1. **에이전트(`MeatosPosAgent.cs`)** — `LooksLikeBarcode`가 순수 숫자 8~14자리(또는 `2`+12자리)만 통과 → 저울/POS가 찍는 규격외 코드(영문·하이픈 등)는 **서버로 전송조차 안 됨**.
2. **관찰 RPC(`capture_pos_sale_observation_agent`)** — 형식 미준수 코드는 `INVALID_BARCODE`로 **아무것도 기록 안 하고 버림**. 매핑돼도 `WEIGHT_EMBED`/`FIXED`에 단가 없으면 `SALE_VALUE_REQUIRED`로 빠져 관찰기록 미생성.

데이터 흐름: **계산대 바코드 스캐너(키보드 웨지) → 에이전트(.exe, 트레이 상주) → Supabase RPC → `scan_event` 기록**. connect.html의 "실시간 스캔 로그"는 **DB를 보는 뷰어**일 뿐(크롬 꺼도 수집 계속).

## 3. 적용한 수정 (기능)

### 3-1. DB 관찰 함수 교체 (라이브 적용 완료)
신규 마이그레이션 `supabase/migrations/202608310101_pos_capture_all_field_observation.sql` 로 `capture_pos_sale_observation_agent` 를 `create or replace`:
- **규격외 코드도 원본 그대로 `scan_event` 기록**(거래ID 없는 연결 프로브 `barcode='x'`는 기존대로 `INVALID_BARCODE`만 반환해 연결확인 유지).
- **매핑된 스캔은 계산 가능 여부와 무관하게 항상 `OBSERVED`로 기록**(단가 미설정 등은 note로 사유 표기).
- 매출·재고는 절대 변경 안 함(shadow 전용).
- **적용 방법**: Supabase SQL Editor에 직접 붙여넣기 실행("Success. No rows returned"). ← MCP 커넥터가 이 프로젝트 권한 없어서 SQL Editor로 진행.

### 3-2. 에이전트 필터 완화 (`MeatosPosAgent.cs`)
`LooksLikeBarcode`를 서버 규격 `^[0-9A-Za-z._-]{6,64}$` 에 맞춰 확장 → 규격외 코드도 전송. 사람 손입력은 기존 스캐너 속도 판정(TOO_SLOW/TYPED_BY_HAND)으로 계속 걸러짐.

### 3-3. 에이전트 하드닝 (후반 추가, `version=2026-09-01-resilient`)
"설치 후 되다가 멈춤" 대응:
- **60초 watchdog로 저수준 키보드 훅 자동 재설치**(절전/잠금 후 훅이 조용히 풀리는 것 방지).
- **절전 해제(Resume)·세션 잠금해제 시 즉시 재훅**.
- **10분마다 HEARTBEAT 로그**(살아있는지 확인용).
- 훅 콜백 try/catch 방어.

### 3-4. 설치본 버전 표기 (혼란 방지)
- `connect.html`: 설치본 fetch에 `?v=Date.now()`(캐시 무력화, 항상 최신) + 다운로드 파일명에 **날짜 포함**(`MEATOS-POS-설치-POS01-YYYYMMDD.exe`).
- `build-pos-installer.ps1`: 빌드 시 `downloads/MEATOS-POS-Setup.version.txt`(빌드일·SHA) + 날짜 사본(`MEATOS-POS-Setup-YYYYMMDD.exe`) 생성. → `/downloads/MEATOS-POS-Setup.version.txt`로 배포본 확인.

## 8. 배포 파이프라인 (정리)

```powershell
cd C:\MEATOS

# 1) 에이전트/설치본 재빌드 (Windows + .NET Framework csc 필요)
npm run pos:build
#   → downloads\MEATOS-POS-Setup.exe (+ .sha256, .version.txt, 날짜사본)
#   → 콘솔에 BuildDate/BuildStamp/SetupSha256 출력

# 2) 미리보기 배포 (운영 안 건드림) — 토큰은 vercel.com/account/tokens 발급
vercel --token <토큰> --yes --archive=tgz
#   → 미리보기 URL (Vercel 로그인 필요한 보호 URL)

# 3) 운영 배포
vercel --prod --token <토큰> --yes --archive=tgz

# 4) 승격 (중요): Vercel 대시보드 → Deployments → 새 배포 ⋯ → Promote to Production
#    (Instant Rollback이 활성이면 도메인이 자동으로 안 넘어감 → 반드시 승격)
```

- Vercel CLI `vercel login`은 **한글 PC 호스트명 때문에 ByteString 오류** 발생 → **`--token` 방식 사용**.
- 파일 개수 초과 오류(`files > 15000`)는 **`--archive=tgz`** 로 우회. `.vercelignore`에 `.venv-ppstructure` 등 무거운 폴더 제외.
- **git push 금지**(자동배포 롤백 방지). 배포는 **CLI로만**.
