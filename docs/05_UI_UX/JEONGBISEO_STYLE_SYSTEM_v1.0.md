# 정육비서 디자인 시스템 헌장

**문서명:** JEONGBISEO_STYLE_SYSTEM_v1.0  
**버전:** 1.0  
**적용 범위:** 정육비서 전체 웹·모바일 화면  
**문서 목적:** 대시보드, 매입, 매출, 재고, 알림, 위생점검, AI 기능 등 모든 화면에 동일한 디자인 언어를 적용하기 위한 최상위 기준 문서

---

## 1. 디자인 시스템 선언

정육비서는 일반 제조 ERP처럼 복잡하고 무거운 화면을 지향하지 않는다.

정육점과 식당 운영자가 별도의 교육 없이도 사용할 수 있도록 다음 원칙을 따른다.

> **정육점 사장님이 매일 사용하는 쉽고 신뢰할 수 있는 디지털 비서**

화면은 업무 시스템답게 정확해야 하지만, 오래된 ERP처럼 보이지 않아야 한다.

최종 인상은 다음 세 문장으로 정의한다.

- 보기 쉽다.
- 지금 해야 할 일이 바로 보인다.
- 숫자를 신뢰할 수 있다.

## 2. 디자인 핵심 키워드

### 2.1 핵심 키워드

- Professional
- Premium
- Clean
- Reliable
- Simple
- Operational
- Friendly
- Data First

### 2.2 사용자 인상

사용자가 화면을 처음 보았을 때 다음 느낌을 받아야 한다.

- 정육업에 맞는 전문 프로그램이다.
- 복잡하지 않고 바로 사용할 수 있다.
- 중요한 숫자와 알림이 잘 보인다.
- 소비자 쇼핑몰이 아니라 사업 운영 도구다.
- 오래 사용해도 눈이 피로하지 않다.

### 2.3 지양해야 할 인상

- 유아적인 색상
- 지나친 파스텔
- 아이콘 중심 소비자 앱
- 장식이 많은 카드
- 과도한 그라데이션
- 색상이 너무 많은 글씨
- 작은 글씨와 좁은 버튼
- 정보가 반복되는 대시보드
- 의미 없는 애니메이션
- 오래된 Windows ERP 화면

## 3. 브랜드 아이덴티티

### 3.1 브랜드명

**정육비서**

### 3.2 브랜드 슬로건

**매입부터 판매까지, 한눈에 관리**

### 3.3 브랜드 성격

정육비서는 사용자를 통제하는 ERP가 아니라 사용자를 돕는 업무 비서다.

따라서 문구는 명령형보다 안내형을 우선한다.

권장:

- 고기가 들어왔어요
- 거래명세서를 촬영해 주세요
- 오늘 확인할 알림이 2건 있습니다
- 위생점검표 작성이 완료됐습니다

지양:

- 입고 트랜잭션 실행
- 데이터 등록
- 프로세스 처리
- 작업 수행

## 4. 디자인 방향

### 4.1 기본 테마

전체 페이지는 **밝은 라이트 테마**를 기본으로 한다.

- 배경: 매우 밝은 회색
- 주요 카드: 흰색
- 헤더: 흰색 또는 아주 옅은 회색
- 텍스트: 검정 및 진한 회색
- 브랜드 포인트: 정육비서 레드
- 정보 포인트: 블루
- 완료 상태: 그린
- 주의 상태: 오렌지
- 위험 및 알림: 레드

### 4.2 화면의 우선순위

모든 화면은 아래 순서를 따른다.

1. 현재 위치와 화면 제목
2. 핵심 숫자 또는 현재 상태
3. 사용자가 지금 해야 할 작업
4. 상세 목록 또는 분석 정보
5. 보조 정보

### 4.3 데이터 우선 원칙

아이콘보다 숫자가 우선이다.

카드에서 가장 먼저 보여야 하는 것은 다음 중 하나다.

- 금액
- 건수
- 상태
- 날짜
- 처리 필요 여부

아이콘은 의미를 빠르게 이해하도록 돕는 보조 요소로만 사용한다.

- 작성완료: 그린
- 유통기한 임박: 오렌지
- 알림 및 미작성: 레드
- 증가·감소 추이: 레드 또는 블루

하나의 카드 안에서 강조색은 최대 2개까지만 사용한다.

## 6. 타이포그래피

### 6.1 기본 폰트

```css
font-family:
  "Pretendard",
  -apple-system,
  BlinkMacSystemFont,
  "Segoe UI",
  "Noto Sans KR",
  sans-serif;
```

### 6.2 글자 크기 체계

| 용도 | Desktop | Tablet | Mobile | 굵기 |
|---|---:|---:|---:|---:|
| 페이지 제목 | 32px | 28px | 24px | 700 |
| 주요 섹션 제목 | 24px | 22px | 20px | 700 |
| 카드 제목 | 18px | 17px | 16px | 600~700 |
| KPI 금액 | 40px | 34px | 28px | 700 |
| KPI 건수 | 34px | 30px | 26px | 700 |
| 본문 | 16px | 15px | 14px | 400~500 |
| 보조 문구 | 14px | 13px | 12px | 400 |
| 메타 정보 | 13px | 12px | 11px | 400 |

### 6.3 숫자 표현 규칙

- 금액은 3자리 콤마를 사용한다.
- 원화 기호는 `₩` 또는 `원` 중 페이지 안에서 하나만 사용한다.
- 경영 현황은 금액과 단위를 분리해 읽기 쉽게 표현한다.
- 숫자는 탭 또는 표에서도 우측 정렬한다.
- 소수점은 실제 업무에 필요한 경우만 사용한다.

예:

```text
145,320,000원
12건
1,245종
3일 이내
```

## 8. 모서리와 그림자

### 8.1 Border Radius

| 요소 | 값 |
|---|---:|
| 큰 패널 | 16px |
| 일반 카드 | 14px |
| 작은 카드 | 12px |
| 버튼 | 10px |
| 입력창 | 10px |
| 배지 | 999px |

카드를 지나치게 둥글게 만들지 않는다.

### 8.2 Shadow

기본 카드:

```css
box-shadow: 0 4px 18px rgba(16, 24, 40, 0.06);
```

Hover 카드:

```css
box-shadow: 0 8px 26px rgba(16, 24, 40, 0.10);
```

오버레이 및 모달:

```css
box-shadow: 0 18px 48px rgba(16, 24, 40, 0.16);
```

그림자는 약하게 사용하고, 카드 구분은 테두리와 배경 차이를 우선한다.

## 10. 공통 헤더

### 10.1 구성

왼쪽:

- 정육비서 로고
- 브랜드명
- 슬로건

오른쪽:

- 로그인 또는 사용자 정보
- 햄버거 메뉴

### 10.2 규칙

- 좌측 고정 사이드바를 기본 화면에 상시 노출하지 않는다.
- 메뉴는 우측 상단 햄버거 버튼으로 연다.
- 로그인은 햄버거 왼쪽에 배치한다.
- 알림 아이콘은 로그인 이후 사용자 헤더에서만 노출한다.
- 헤더 높이는 80~96px 범위로 유지한다.

## 11. 대시보드 구조

메인 대시보드는 다음 순서를 유지한다.

1. 오늘의 AI 브리핑
2. 고기가 들어왔어요 CTA
3. 하단 KPI 카드 4개
4. 필요 시 그래프
5. 최근 거래

### 11.1 오늘의 AI 브리핑

구성:

- 제목: 오늘의 AI 브리핑
- 기준일: 날짜만 표시
- 새로고침 버튼
- 당월 경영 현황

당월 경영 현황은 3행으로 구성한다.

#### 1행: 매출·매입

매출과 매입을 같은 행에 나란히 배치한다.

```text
매출                         매입
145,320,000원               102,850,000원
전월 대비 +12.4%            전월 대비 -5.6%
```

#### 2행: 유통기한 임박

```text
유통기한 임박                         3건
```

#### 3행: 위생점검표

```text
위생점검표                           ● 작성완료
```

상태에 따라:

```text
● 작성완료
● 미작성
```

작성완료는 그린, 미작성은 레드로 표시한다.

AI 브리핑 내부에서 불필요한 세로 카드 분리는 사용하지 않는다.

### 11.2 새로고침

- 기준일 우측에 배치
- 최소 터치 영역 44px
- 새로고침 중 회전 애니메이션 표시
- 갱신 완료 후 짧은 토스트 표시
- 기준일은 `YYYY.MM.DD` 형식

## 12. 고기가 들어왔어요 CTA

정육비서의 핵심 매입 진입 버튼이다.

### 12.1 구성

왼쪽:

- 정육 또는 거래명세서 관련 작은 이미지/아이콘
- 제목: 고기가 들어왔어요!
- 설명: 거래명세서를 촬영해 입고를 시작합니다.

오른쪽:

- 거래명세서 촬영 버튼
- 카메라 아이콘

### 12.2 스타일

- 흰색 또는 아주 옅은 레드 배경
- 얇은 브랜드 레드 테두리
- 강한 그라데이션 금지
- 버튼만 브랜드 레드 사용
- CTA 전체 높이를 과도하게 키우지 않는다.

## 13. 하단 KPI 대시보드 카드

고정 4개 카드:

1. 매입현황
2. 매출현황
3. 재고현황
4. 알림현황

### 13.1 카드 공통 구조

```text
작은 아이콘
카드 제목
기간 또는 범위
주요 수치
보조 설명
추이 또는 상세 항목
```

### 13.2 매입현황

- 오늘 매입 건수
- 오늘 매입 금액
- 전일 또는 전월 대비
- 정육점에서는 부족재고 관리 개념을 기본 카드에 표시하지 않는다.

### 13.3 매출현황

- 오늘 매출 건수
- 오늘 매출 금액
- 전일 또는 전월 대비
- 당일 기준 정보임을 명확히 표시한다.

### 13.4 재고현황

- 전체 품목 수
- 현재 재고 금액
- 전월 대비 변동
- 품목 또는 금액 중 하나를 주요 수치로 선택한다.

### 13.5 알림현황

알림 수치는 아래 항목을 포함한다.

- 유통기한 임박 건수
- 위생일지 또는 위생점검표 미작성
- 서버 공지 확인 필요 건수

알림 총 건수에는 유통기한 임박 건수도 포함한다.

예:

```text
알림현황
확인 필요 2건

유통기한 임박 0건
위생일지 작성 완료
서버 공지 확인 필요 2건
```

알림 카드에서만 레드 강조를 적극적으로 사용한다.

## 14. 카드 컴포넌트

### 14.1 기본 카드

```css
.ui-card {
  background: var(--bg-card);
  border: 1px solid var(--border-default);
  border-radius: 14px;
  box-shadow: 0 4px 18px rgba(16, 24, 40, 0.06);
  padding: 24px;
}
```

### 14.2 KPI 카드

필수 정보:

- 제목
- 기준 기간
- 대표 수치
- 보조 수치
- 상태 또는 추이
- 클릭 가능한 경우 이동 표시

카드 전체가 클릭 가능하면 내부에 별도의 작은 버튼을 중복 배치하지 않는다.

### 14.3 상태 카드

상태는 색상과 글자를 함께 사용한다.

```text
● 작성완료
● 미작성
● 확인 필요
● 정상
```

색상만으로 상태를 구분하지 않는다.

- 자동으로 모두 적용했습니다.

### 24.3 AI 결과 적용

## 31. 구현 금지 사항

다음은 명시적으로 금지한다.

- 기본 화면에 좌측 고정 사이드바를 임의로 추가
- 카드마다 서로 다른 색상 사용
- 주요 글씨를 여러 색으로 표현
- 한 카드에 3개 이상의 강조색 사용
- AI 화면에 보라색 그라데이션 남용
- 유통기한과 위생점검을 별도 대형 KPI 카드로 중복 표시
- 알림현황 카드를 위생점검표 카드로 변경
- 매입현황과 입고현황을 혼용
- 오늘 수치와 당월 수치를 같은 라벨로 표시
- 작은 아이콘을 주요 정보보다 크게 표시
- 기능이 없는 장식 버튼 추가
- 표보다 카드가 보기 좋다는 이유로 업무 데이터를 모두 카드로 변경
- 실데이터 연동 전 정확한 값처럼 과장

## 32. 최종 검수 체크리스트

### 브랜드

- 정육비서 로고와 슬로건이 올바르게 표시되는가?
- 브랜드 레드를 핵심 동작에만 사용했는가?

- 기본 텍스트가 검정 계열인가?
- 상태 외 텍스트에 색상을 남용하지 않았는가?
- 알림현황만 레드 중심으로 강조했는가?

### 대시보드

- AI 브리핑이 3행 구조인가?
- 매출·매입이 같은 행인가?
- 유통기한 임박이 한 행인가?
- 위생점검표가 한 행인가?
- 하단 4번째 카드가 알림현황인가?
- 고기가 들어왔어요 CTA가 유지됐는가?

### 사용성

- 50대 사용자가 숫자와 버튼을 쉽게 읽을 수 있는가?
- 모바일에서 터치 영역이 44px 이상인가?
- 핵심 작업이 1~2번의 클릭으로 가능한가?

### 데이터

- 오늘, 당월, 전체 기준이 명확한가?
- 금액, 건수, 품목 수 단위가 일관적인가?
- 같은 정보가 여러 카드에 중복되지 않는가?

### 반응형

- 390px에서 가로 스크롤이 불필요하게 발생하지 않는가?
- 768px에서 카드가 자연스럽게 2열로 바뀌는가?
- 1024px 이상에서 화면이 지나치게 넓어지지 않는가?

## 33. 개발자 작업 지시문

정육비서 화면을 새로 만들거나 수정할 때 다음 순서로 작업한다.

1. 이 문서를 먼저 읽는다.
2. 기존 화면과 데이터 구조를 확인한다.
3. 공통 토큰과 공통 클래스를 재사용한다.
4. 화면별 임의 색상과 임의 간격을 추가하지 않는다.
5. 기존 업무 흐름과 데이터는 유지한다.
6. 모바일과 데스크톱을 함께 구현한다.
7. 작업 후 대시보드와 대표 업무 페이지를 시각 검수한다.
8. 커밋·푸시·배포는 사용자 승인 전 실행하지 않는다.
