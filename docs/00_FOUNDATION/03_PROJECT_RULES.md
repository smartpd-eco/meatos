# MEATOS Project Rules

**Version**: 1.0\
**Author**: SmartPD\
**Status**: Active\
**Last Update**: 2026-07-10

------------------------------------------------------------------------

# 1. 목적

본 문서는 MEATOS 프로젝트의 실무 개발 규칙을 정의한다. 모든 개발자는
새로운 기능을 구현하기 전에 본 문서를 확인한다.

------------------------------------------------------------------------

# 2. 기본 원칙

-   문서를 먼저 작성하고 개발한다.
-   작은 기능부터 완성한다.
-   완료된 기능은 항상 테스트한다.
-   개발보다 유지보수를 우선 고려한다.

------------------------------------------------------------------------

# 3. 개발 순서

1.  요구사항(PRD) 확인
2.  MD 문서 작성
3.  DB 영향 검토
4.  UI 설계
5.  개발
6.  테스트
7.  Git Commit
8.  Git Push

------------------------------------------------------------------------

# 4. 기능 추가 규칙

새로운 기능은 반드시 아래 질문을 확인한다.

-   기존 기능을 재사용할 수 있는가?
-   기존 DB를 활용할 수 있는가?
-   재고 흐름에 영향을 주는가?
-   Event Log가 필요한가?
-   사용자 업무를 줄여주는가?

하나라도 검토되지 않았다면 개발을 시작하지 않는다.

------------------------------------------------------------------------

------------------------------------------------------------------------

# 6. Git 운영 규칙

Commit 메시지는 목적이 명확해야 한다.

예시

-   feat: 상품관리 추가
-   fix: 재고 계산 오류 수정
-   docs: PROJECT_RULES 업데이트
-   refactor: Inventory Engine 개선

작업 완료 후 반드시 Push하여 백업한다.

------------------------------------------------------------------------

# 7. 문서 관리 규칙

-   Foundation 문서는 신중하게 수정한다.
-   변경 시 Version을 올린다.
-   문서와 코드가 일치해야 한다.
-   완료된 문서는 삭제하지 않고 History로 이동한다.

------------------------------------------------------------------------

# 8. AI 개발 규칙

Codex, Claude Code 등 AI는

-   기존 문서를 먼저 확인한다.
-   중복 기능을 만들지 않는다.
-   Core와 Plugin을 구분한다.
-   구현 이유를 설명할 수 있어야 한다.

------------------------------------------------------------------------

# 9. 우리의 약속

우리는 빠르게 만드는 것보다 오랫동안 사용할 수 있는 프로그램을 만든다.

항상

**하나씩, 꾸준히, 완성해 나간다.**
