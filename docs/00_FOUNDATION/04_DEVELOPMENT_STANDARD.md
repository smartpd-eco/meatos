# MEATOS Development Standard

**Version**: 1.0\
**Author**: SmartPD\
**Status**: Active\
**Last Update**: 2026-07-10

------------------------------------------------------------------------

# 1. 목적

본 문서는 MEATOS의 실제 개발 표준을 정의한다. 모든 기능은 본 문서를
기준으로 설계·개발·테스트한다.

------------------------------------------------------------------------

# 2. 개발 철학

MEATOS는 기능 중심이 아닌 **Engine 중심**으로 개발한다.

Engine → Service → UI

UI는 언제든 변경할 수 있지만 Engine은 쉽게 변경하지 않는다.

------------------------------------------------------------------------

# 3. Core 우선순위

1.  Product Engine
2.  Inventory Engine
3.  Event Engine
4.  AI Engine

새로운 기능은 반드시 어느 Engine에 속하는지 먼저 결정한다.

------------------------------------------------------------------------

# 4. Plugin 원칙

POS, OCR, 알림톡, 정부 API는 모두 Plugin이다.

Plugin은 Core를 수정하지 않는다. Adapter를 통해 Core와 연결한다.

------------------------------------------------------------------------

# 5. Inventory First

모든 업무 흐름은 Inventory Engine을 기준으로 한다.

입고 → 현재고 → 출고 → 재고조정 → Ledger → History → AI → 통계

재고를 우회하는 기능은 만들지 않는다.

------------------------------------------------------------------------

# 6. Event Driven

중요한 업무는 Event를 생성한다.

예시 - 거래명세서 등록 - OCR 완료 - Alias 확정 - 입고 완료 - POS 판매 -
재고 차감 - 발주 생성

Event는 감사, 이력관리, AI 분석의 기반이 된다.

------------------------------------------------------------------------

# 7. 개발 순서

1.  PRD 확인
2.  MD 작성
3.  DB 설계
4.  API 설계
5.  UI 설계
6.  Engine 개발
7.  Service 개발
8.  화면 연결
9.  테스트
10. Git Commit & Push

문서 없이 개발하지 않는다.

------------------------------------------------------------------------

# 8. 폴더 원칙

-   docs : 문서
-   apps : 실행 프로젝트
-   packages : 공통 라이브러리
-   services : 비즈니스 로직
-   adapters : POS/API/OCR 연결
-   ai : AI 기능

폴더 역할을 혼합하지 않는다.

------------------------------------------------------------------------

# 9. Git 규칙

-   작은 단위로 Commit
-   작업 종료 시 Push
-   Commit 메시지는 목적 중심

예) - feat: - fix: - docs: - refactor: - chore:

------------------------------------------------------------------------

# 10. 완료 기준 (Definition of Done)

기능은 아래 조건을 모두 만족해야 완료로 본다.

-   PRD 반영 완료
-   MD 수정 완료
-   DB 정상 동작
-   UI 연결 완료
-   테스트 완료
-   Git Push 완료

------------------------------------------------------------------------

# 11. 품질 원칙

-   중복 코드를 만들지 않는다.
-   하드코딩을 최소화한다.
-   기존 데이터를 깨지 않는다.
-   사용자 업무를 줄이는 방향으로 개발한다.

------------------------------------------------------------------------

# 12. MEATOS 개발 약속

우리는 빠른 개발보다 오랫동안 유지할 수 있는 구조를 만든다.

오늘 하나를 완성하고, 내일 하나를 더 쌓는다.

**한 번에 완벽하게 만들지 않는다. 하나씩, 꾸준히, 완성해 나간다.**
