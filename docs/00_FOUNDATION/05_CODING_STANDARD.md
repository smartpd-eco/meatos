# 05_CODING_STANDARD.md

# MEATOS Coding Standard

**Version**: 1.0\
**Author**: SmartPD\
**Status**: Active\
**Last Update**: 2026-07-10

------------------------------------------------------------------------

# 1. 목적

본 문서는 MEATOS 프로젝트의 코드 작성 기준을 정의한다. 모든 개발자와
AI(Codex, Claude Code 등)는 동일한 규칙으로 코드를 작성한다.

------------------------------------------------------------------------

# 2. 기본 원칙

-   읽기 쉬운 코드가 좋은 코드다.
-   중복보다 재사용을 우선한다.
-   하드코딩을 지양한다.
-   코드보다 업무 흐름을 먼저 이해한다.

------------------------------------------------------------------------

# 3. 폴더 구조

``` text
apps/         실행 프로젝트
services/     비즈니스 로직
packages/     공통 모듈
adapters/     POS, OCR, API 연동
ai/           AI 기능
docs/         프로젝트 문서
```

각 폴더의 역할을 혼합하지 않는다.

------------------------------------------------------------------------

# 4. 파일명 규칙

-   kebab-case 사용
-   의미 있는 이름 사용

예시

-   inventory-service.ts
-   product-alias.ts
-   supplier-api.ts

지양

-   test.ts
-   new.ts
-   temp.ts

------------------------------------------------------------------------

# 5. 함수 작성 규칙

하나의 함수는 하나의 역할만 수행한다.

좋은 예

-   createPurchase()
-   updateInventory()
-   syncPosSales()

지양

-   processAll()
-   doWork()

------------------------------------------------------------------------

# 6. 컴포넌트 규칙

UI는 비즈니스 로직을 최소화한다.

Engine → Service → UI

UI는 Service를 호출만 한다.

------------------------------------------------------------------------

# 7. 데이터 규칙

상품명은 항상 Product Master를 기준으로 한다.

별칭(Alias)은 Alias Engine에서 관리한다.

재고 변경은 반드시 Inventory Engine을 통해 처리한다.

------------------------------------------------------------------------

# 8. 로그 규칙

오류는 숨기지 않는다.

중요 작업은 Event Log를 남긴다.

-   입고
-   출고
-   재고조정
-   POS 판매
-   발주
-   AI 추천

------------------------------------------------------------------------

# 9. API 규칙

-   REST 방식 유지
-   명확한 URL 사용
-   일관된 응답 형식

예시

GET /products

POST /inventory/inbound

POST /inventory/outbound

------------------------------------------------------------------------

# 10. Commit 규칙

예시

docs: 문서 수정

feat: 기능 추가

fix: 오류 수정

refactor: 구조 개선

test: 테스트

chore: 기타

------------------------------------------------------------------------

# 11. AI 코드 작성 규칙

AI는 구현 전에 반드시 확인한다.

-   기존 코드 재사용 가능한가?
-   Core Engine을 수정하는가?
-   Plugin으로 해결 가능한가?
-   Event Log가 필요한가?

------------------------------------------------------------------------

# 12. 금지 사항

-   하드코딩
-   중복 코드
-   임시 코드 방치
-   사용하지 않는 파일 생성
-   테스트 없이 Push

------------------------------------------------------------------------

# 13. 우리의 코딩 문화

우리는 화려한 코드를 작성하지 않는다.

누가 보더라도 이해할 수 있는 코드를 작성한다.

**좋은 코드는 시간이 지나도 읽히는 코드이다.**
