# MEATOS 스캔 캡처 에이전트 — 개발·설치 문서 (DEV)

작성일: 2026-07-24
상태: **캡처 가능 확정** (벽산정육점 POS PC 메모장 테스트에서 스캐너 입력 `2090120232502` 정상 수신)
구성: ① MEATOS 서버 수신부(완성) + ② POS PC 캡처 에이전트(본 문서, 별도 앱)

---

## 0. 전체 그림

```
계산대 바코드 스캐너(키보드형)
   │  스캔 = "2090120232502" + Enter
   ├───────────▶ 기존 POS (그대로 계산)         ← 무침습
   └──(동시 읽기)──▶ 캡처 에이전트(AHK, POS PC)
                         │  13자리 '2' 시작 바코드만 필터 + 디바운스
                         ▼  POST /rest/v1/scan_event {tenant_id, barcode, device}
                   MEATOS 서버(트리거 process_scan_event)
                         │  품목코드(2~7) + 금액(8~12) 파싱 → product_barcode 매핑
                         ▼
                 inventory_movement OUT + sales_record(STORE)  ← 재고 자동 차감·매출
```

바코드 해독(실측): `2 | 090120 | 24000 | 2` = 프리픽스 · **품목코드** · **금액(원)** · 체크.
중량 = 금액 ÷ (100g단가×10). 예: 24000 ÷ 125000 = 0.192kg(192g) ✔

## 2. 에이전트 동작 원리 (AutoHotkey v2)

- **InputHook("V")**: 키 입력을 **가로채지 않고(Visible)** 읽는다 → POS는 스캔을 정상 수신(무침습).
- Enter로 끝나는 입력을 모아 **`^2\d{12}$`(13자리·2시작) 인 것만** 판매 스캔으로 인정 → 수기 타이핑·다른 입력은 자동 무시.
- **디바운스**(기본 2초): 같은 바코드 중복 전송 방지.
- WinHttp로 Supabase `scan_event` 에 POST. 나머지(품목 매칭·재고 차감·매출)는 서버 트리거가 처리.

> 저울(소분/라벨발행)은 스캐너로 안 찍히므로 캡처되지 않음 → **판매 스캔만** 잡힌다(소분/판매 자연 분리).

---

## 3. 설치 (매장 POS PC)

1. **AutoHotkey v2** 설치: https://www.autohotkey.com (v2.0 이상)
2. `agent/meatos-scan-agent.ahk` 를 POS PC로 복사.
3. 파일 상단 **설정값** 수정:
   - `TENANT_ID` : 매장(회사) ID
   - `DEVICE` : 단말 이름(예: POS01)
   - (SUPA_URL/ANON_KEY 는 그대로)
4. 더블클릭 실행 → 트레이 아이콘 표시(“실행 중”).
5. (권장) **.exe 컴파일**(Ahk2Exe) 후 **시작프로그램 등록**(`shell:startup` 폴더에 바로가기) → 부팅 시 자동 실행.

---

## 4. 테스트 절차 (설치 후 검증)

1. **매핑 1회 등록**: MEATOS `판매 스캔`(sell.html)에서 품목코드 `090120` = "한우채끝등심", 100g단가 `12500` 등록.
   또는 SQL:
   ```sql
   insert into public.product_barcode(tenant_id,barcode_key,raw_product_name,unit,default_price,weigh_type)
   values ('881f6cc1-b552-468c-b9b4-152edb464e61','090120','냉장 한우채끝등심',' kg',125000,'PRICE_EMBED');
   ```
2. 에이전트 실행 상태에서 **라벨을 계산대 스캐너로 스캔**.
3. 확인:
   ```sql
   select status, matched_product, note, barcode from public.scan_event order by scanned_at desc limit 5;
   ```
   → `PROCESSED / 한우채끝등심` 이면 성공.
4. **재고 화면**에서 채끝등심 수량이 스캔한 중량만큼 줄었는지, **매출**에 STORE 채널로 기록됐는지 확인.

## 5. 예외·튜닝

| 상황 | 처리 |
|---|---|
| 미등록 바코드 | `scan_event.status=PENDING` → sell.html에서 품목 1회 지정 후 재스캔 |
| 취소/반품 | POS 취소분은 MEATOS에서 수동 취소(재고 IN 보정) — 관리 UI 예정 |
| 중복 스캔 | 에이전트 디바운스 2초 + (필요시) 서버측 중복 정책 추가 |
| 바코드 포맷 다른 매장 | 트리거의 파싱 규칙(품목코드/금액 위치)만 매장별 조정 |
| 수기 입력 오탐 | `^2\d{12}$` 필터로 대부분 차단(계산대에서 13자리 2시작 수기입력은 사실상 없음) |

## 6. 보안·안정성

- 에이전트는 입력을 **읽기만**(V 옵션) → POS 동작 불변.
- 전송 데이터 = **바코드·단말명뿐**(고객정보 없음), HTTPS 암호화.
- anon 키는 웹앱과 동일한 공개키 수준(민감정보 아님). 매장별 분리가 필요하면 향후 매장 토큰 도입.
- 서버 트리거 `SECURITY DEFINER` + `search_path=public` 로 안전 실행.

---

## 7. 다매장 확장 (범용성)

- 스캐너가 **키보드형(HID)** 인 매장은 이 에이전트 그대로 적용 → **POS 브랜드 무관**.
- 시리얼(COM) 스캐너 → 포트 분기 버전, 안드로이드 POS → 별도 앱(로드맵).
- 매장별로 바코드 파싱 규칙만 프로파일화하면 됨.

---

## 8. 향후 개선(로드맵)

1. 서버측 중복/취소 처리 + 감사 로그 뷰.
2. 미등록(PENDING) 알림 → 관리자 화면에서 원터치 매핑.
3. .exe 인스톨러(설정 마법사: 매장ID·단말명 입력) + 원격 업데이트.
4. 저울 데이터 직접 연동(중량내장 라벨 매장 대응).
5. 배달(쿠팡) 주문 → 동일 scan_event 경로로 재고 차감(매출·정산은 별도).

---

## 9. 요약

- **캡처 확정** → 남은 건 에이전트 설치·검증뿐.
- 서버 수신부/재고·매출 로직은 이미 완성. 에이전트는 "13자리 바코드를 서버로 던지는" 가벼운 프로그램.
- 이 방식은 **POS를 안 가리므로** 다른 매장에도 그대로 확장 가능 = MEATOS SaaS의 핵심 무기.
