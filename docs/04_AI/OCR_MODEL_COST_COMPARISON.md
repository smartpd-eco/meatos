# MEATOS OCR 모델 비교 · 비용 분석 (Flash vs Flash-Lite)

**작성일:** 2026-07-20
**대상 함수:** Supabase Edge Function `analyze-invoice`
**현재 적용 모델:** `gemini-3.1-flash-lite` (자동 선택, thinking 비활성화)

---

## 1. 결론 요약

거래명세서 인식은 **Gemini 3.1 Flash-Lite**로 확정한다.

- 속도: 웜 상태 **2.8~3.1초** (첫 호출 약 4.9초). 목표(3~5초) 충족.
- 비용: 스캔 1장당 **약 2~3원** (Flash 대비 절반).
- 정확도: 인쇄된 거래명세서 품목·금액 추출에 충분.

속도가 이탈률을 좌우하고(유료 서비스에서 16초는 소비자 이탈), 인쇄 문서 판독은 Lite로도 정확도가 충분하므로 Flash-Lite가 최적이다.

---

## 2. Flash vs Flash-Lite 차이

| 항목 | Gemini 3.1 **Flash-Lite** (현재) | Gemini 3 **Flash** |
|---|---|---|
| 설계 목적 | 최고 속도·최저 비용, 대량 처리 | 고난도 추론·복잡 문서 |
| 속도 | 가장 빠름 (2.5 Flash 대비 TTFT 2.5배↑, 출력 45%↑) | 보통 |
| 입력 단가 | **$0.25 / 100만 토큰** | $0.50 / 100만 토큰 |
| 출력 단가 | **$1.50 / 100만 토큰** | $3.00 / 100만 토큰 |
| 멀티모달(이미지) | 지원 | 지원 |
| 구조화 출력(JSON) | 지원 | 지원 |
| 적합 용도 | **거래명세서 OCR**, 반복 처리 | 손상·비정형·복잡 레이아웃 |

핵심 차이: Flash-Lite는 **속도·단가 최적화** 버전이고, Flash는 **추론 성능**이 필요한 어려운 작업용이다. 정형화된 인쇄 명세서 판독에는 Lite가 속도·비용 모두 우수하며 품질 저하가 거의 없다.

> 추가로, 두 모델 모두 "thinking(내부 추론)"을 끄면(`thinkingBudget: 0`) 지연이 크게 줄고 일정해진다. MEATOS는 이 옵션을 적용했다. (thinking 켜짐 상태에서 9~30초로 요동치던 것이 3초 안팎으로 안정화)

---

## 3. 스캔 1장당 비용 추정

거래명세서 1장 기준 대략적인 토큰 사용량(추정): 입력 ≈ 1,500 토큰(이미지+프롬프트), 출력 ≈ 800 토큰(품목 JSON).

| 모델 | 입력 비용 | 출력 비용 | **1장 합계(추정)** |
|---|---|---|---|
| **Flash-Lite** | 1,500 × $0.25/1M = $0.00038 | 800 × $1.50/1M = $0.0012 | **≈ $0.0016 (약 2.3원)** |
| Flash | 1,500 × $0.50/1M = $0.00075 | 800 × $3.00/1M = $0.0024 | ≈ $0.0032 (약 4.6원) |

> 환율 약 1,400원/$ 기준. 이미지 토큰은 해상도·타일 수에 따라 달라지므로 실제 값은 ±로 변동할 수 있음.

## 5. 모델 전환 방법 (코드 수정 없이)

함수는 사용 가능한 flash 계열 모델을 자동 조회해 **lite를 우선** 선택한다. 특정 모델로 고정하려면 Supabase 시크릿에 다음을 설정한다.

```
GEMINI_VISION_MODEL = gemini-3.1-flash-lite   (또는 원하는 모델명)
```

- 더 높은 정확도가 필요하면 값을 정확도 우선 모델(예: 최신 Flash)로 바꾸면 된다.
- 값을 비우면 자동 선택(lite 우선)으로 동작한다.

설정 위치: Supabase Dashboard → Project → Edge Functions → Secrets. 변경 후 함수 재배포 없이 다음 콜드 스타트부터 반영된다.

---

## 6. 남은 개선 여지 (선택)

- **이미지 해상도 조정:** 현재 1600px 축소. 더 낮추면(예: 1280px) 입력 토큰↓ → 더 빠르고 저렴하지만 작은 숫자 판독 위험. 정확도와 균형 필요.
- **사진 촬영 경로 보정:** 촬영본은 기울기·반사로 합계 인식이 흔들릴 수 있음 → OpenCV 보정 강화 또는 재촬영 유도.
- **콜드 스타트:** 첫 호출이 4~5초로 느림(함수 웜업·모델 조회). 예열 핑 또는 `GEMINI_VISION_MODEL` 고정으로 조회 단계 생략 가능.
